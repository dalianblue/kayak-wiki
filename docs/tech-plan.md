# 皮划艇知识库技术方案 v1（1113，待外部评审）

> 目标：多本皮划艇藏书（**扫描版PDF，原件在施主M5 Max**）→ 可检索、可展示、含图片+图说明的
> 知识沉淀系统。类比现有 book-evidence/FAQ 管线但以图为主。授权口径：私用内核，公开层另拍板。

## 一、架构：两层

```
私有层（/root/workspace/kayak-wiki, git私有仓）     公开层（规划: fxmlab.top/kayak/）
raw/books/ 切片卡片+出处页码; raw/assets/ 书图WebP   concepts/ comparisons/ 导出(mkdocs)
内部检索; 书图永不公开                             {{fig:}}占位符→自绘SVG/公开资产
```
版权口径：版权保护表达不保护知识——书图与原文表达不出墙；公开层自话重写+标注出处（书名/页码）。

## 二、内核：Karpathy LLM-wiki 结构（llm-wiki 技能规范）

- `SCHEMA.md`：域词表taxonomy（划法/翻滚/安全救援/读水/装备/环境…）、页面阈值（技术出现于2+书→建页）、
  对照页规范（多书分歧并列+contested标记，不静默覆盖）、出处标记 `^[raw/books/x.md#p12]`
- `concepts/`（技术条目）`comparisons/`（**多书交叉对照=本项目核心增量**）`entities/`（装备/船型/河流）
- 分工：施主管源+验收，agent蒸馏/交叉引用/lint（孤儿页/死链/矛盾巡检）
- Obsidian兼容（施主Mac/手机可直读）；git版本化（论坛消失=平台依赖教训，内核必须自有）

## 三、切图管线（扫描版分支，方案最薄弱环节——诚实声明）

扫描页=整页位图，无内嵌图对象可抽。主案：
1. 整页渲染 200DPI（PyMuPDF）
2. OCR（含坐标）：定位图注锚点——中文技术书图注模式 `图3-5 xxx` / `Figure x-y`
3. 图组裁切：从图注锚点**向上**裁切至上一文本块/页眉（经典启发式：图在图注上方）；
   同页多图按水平投影分割；跨页图组（"图3-5(续)"）合并
4. 裁切质量目标：图组完整、不混入正文；验收=每书抽检20组人工看
5. 输出：最长边1200px WebP（60~120KB）+320px缩略图；卡片含 WebP路径

未决问题：版面分析模型（PP-Structure/LayoutParser类）是否优于图注锚定启发式？
中文竖排/双栏/无编号图注的边例怎么兜？

## 四、说明与蒸馏

- 印刷图注 = OCR所得（作者原话，质量最高）
- VLM补描述：GLM-4V-Flash（智谱免费档，**未实测，假设成立需冒烟**）——输出动作名称/要领/
  装备/图内文字；领域词表注入prompt防术语漂移
- 卡片 = {图组id, 书名/章节/页码, 印刷图注, VLM描述, tags(词表)}
- 批量跑：断点cursor账本（llm-pipeline-batch-distill模式），夜间跑（服务器内存纪律）

## 五、处理位置分工（待评审重点）

- 原件在施主M5 Max；服务器=2c4g(60G ESSD)/公网5Mbps PayByTraffic/内存紧张(available<300MB告警线)
- 方案X：Mac本地跑渲染+切割+OCR+VLM批量（M5 Max性能富裕，不占服务器资源），只上传
  卡片json+WebP成品（每书约100~300MB）
- 方案Y：PDF传服务器全流程（上传~每本几百MB@10Mbps入方向≈4分钟/百MB；渲染占CPU；夜间跑）
- 倾向X（分工与p-literature-download先例一致：重活本地、成品上服务器）

## 六、检索与展示

- v1检索：sqlite FTS5 trigram（中文子串）+tags精确匹配——皮划艇查询词域窄（"翻滚怎么做"级）
- 公开壳：mkdocs-material（wikilinks插件+lunr内置搜索），构建规则强制版权边界：
  只导出 concepts/+comparisons/；`{{fig:图组id}}` 占位符构建时替换为自绘SVG/公开资产，raw/与书图不出墙
- v2（召回不足再上）：智谱embedding向量层，复用FAQ embed_cards_v2模式
- 查询默认卡片直出（图+图注+出处，零LLM成本）；AI解读按需按钮（~0.005元/次）

## 七、容量（1113 API实查口径）

服务器=2c4g/60G ESSD/公网**5Mbps按使用流量计费**(PayByTraffic, ~0.8元/GB；内存告警线available<300MB)。
10000查询/日×4图：缩略图策略流量≈1.6GB/日≈1.3元/日（40元/月量级）；晚高峰峰值1.36Mbps<5Mbps
无排队；全原图最坏4.8GB/日（115元/月）峰值3.4Mbps仍不排队。CPU/内存：静态+sqlite读，可忽略。

## 八、风险清单（自报薄弱点）

1. 扫描版切割质量是最大不确定项——图注锚定启发式对无编号图注/竖排/双栏的鲁棒性未知
2. GLM-4V-Flash免费档的限速与长稳未知（批量几千张时可能限流）
3. OCR质量决定图注与检索质量——中文印刷体实测未知
4. 公开层`{{fig:}}`替换机制若遗漏，书图会泄漏到公开站——需要构建期断言（扫描产物路径黑名单）
5. Mac与服务器两地产物的一致性（清单对账+sha256）需管线保证
